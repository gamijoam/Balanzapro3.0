# ADR-009 — Contrato OpenAPI primero y generación de código

**Estado:** APROBADA (2026-11-26)

## Respaldo del propietario
2026-11-26, Issue #4. El propietario respondió cuatro preguntas:
- "¿Cómo se define la API?" → **"Contrato primero en contracts/"**.
- "¿Con qué se generan los handlers del servidor Go?" → **"oapi-codegen, modo strict"**.
- "Cliente Dart: ¿cuándo y con qué?" → **"Decidir al iniciar Flutter"**.
- "Versionado y errores" → **"/api/v1 + Problem Details"**.

## Decisión
1. **Contrato primero.**
   - El contrato es OpenAPI 3.1, escrito a mano en `contracts/openapi/` y versionado en git. Es la fuente de verdad de la API.
   - El código Go (y más adelante el Dart) se genera desde el contrato y nunca se edita a mano.
   - CI falla si el código generado no coincide con el contrato.
2. **Servidor Go con oapi-codegen en modo strict**, generando interfaces tipadas para chi (ADR-170).
   - Los handlers implementan esas interfaces y solo traducen entre HTTP y los casos de uso: no contienen lógica de negocio (ADR-004, ADR-163).
   - Versiones candidatas, verificadas el 2026-11-26: `github.com/oapi-codegen/oapi-codegen/v2` v2.8.2 (2026-10-31) y `github.com/oapi-codegen/runtime` v1.9.0 (2026-11-10), ambas Apache-2.0.
   - Se fijan en el primer PR que exponga una API, revisando de nuevo versión y licencia (ADR-168).
3. **Cliente Dart:** se generará del mismo contrato. La herramienta (por ejemplo, OpenAPI Generator dart-dio) se elige y prueba al iniciar el proyecto Flutter (BP-003/BP-006).
4. **Convenciones del contrato:**
   - **Versionado:** prefijo `/api/v1`. Dentro de v1 solo se admiten cambios compatibles (agregar endpoints o campos opcionales). Un cambio incompatible abre `/api/v2`, que convive con v1 hasta retirarla.
   - **Errores:** RFC 9457 (`application/problem+json`) con un `code` tipado y estable, y `correlation_id`. Nunca exponen detalles internos ni secretos.
   - **Tipos:** decimales como string (ADR-040), identificadores UUID y fechas en UTC (con la zona de la sucursal para la fecha comercial).
   - **Operaciones de escritura:** llevan un `operation_id` idempotente (ADR-006).
5. **Consultas SQL tipadas:** sqlc sigue diferido (ADR-172). Se reevalúa cuando crezca el número de consultas.

## Consecuencias
- Ningún endpoint comercial se publica antes de cumplir ADR-169 (identidad, autenticación, permisos y auditoría). La prueba `cmd/bpserver/routes_test.go` sigue mandando hasta que una ADR la sustituya.
- Siguen pendientes y no se ratifican aquí: ADR-018 (generadores de plantillas) y ADR-013 (monorepo).
- Una sustitución requiere una nueva ADR.
