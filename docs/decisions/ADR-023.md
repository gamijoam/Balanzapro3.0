# ADR-023 — Módulos declarativos

**Estado:** APROBADA (2026-11-26)

## Respaldo del propietario
2026-11-26, Issue #14. A la pregunta "ADR-023 (módulos declarativos): ¿ratificas este modelo?…", con el modelo descrito abajo, el propietario respondió **"Ratificar, activación por empresa"**.

## Decisión
1. **Compilación estática.** Cada módulo es código Go compilado en el binario; nunca se carga código externo o no confiable en tiempo de ejecución.
2. **Manifiesto en código** por módulo: id estable, versión, dependencias de otros módulos, códigos de permiso que declara (ADR-024), claves de configuración con su esquema (ADR-027) y migraciones propias.
3. **Activación por empresa**, registrada en `module_registry`.
   - Para activar un módulo hacen falta tres cosas: **licencia** que lo incluya (ADR-147), **dependencias activas** y **permiso** de quien lo activa. Licencia, permiso y activación son condiciones distintas y se exigen las tres.
   - Una dependencia no se desactiva mientras un módulo activo la necesite.
4. **Desactivar no borra historia.** Se ocultan las funciones y se bloquean las operaciones nuevas, pero se conservan los datos, la lectura, la exportación y el respaldo, además de los deberes fiscales (ADR-149).
5. **Módulos base siempre activos:** organización, identidad, permisos, configuración y auditoría.

## Consecuencias
- Pruebas de aceptación:
  - no se activa un módulo sin licencia, sin sus dependencias o sin permiso;
  - no se desactiva una dependencia que otro módulo activo necesita;
  - desactivar conserva los datos y la lectura y bloquea las operaciones nuevas;
  - los módulos base no se pueden desactivar;
  - la activación de una empresa no afecta a otra (SEC-01).
- Se implementa en BP-009, dividida en PRs según AGENTS.md.
- Una sustitución requiere una nueva ADR.
