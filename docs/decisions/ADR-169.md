# ADR-169 — Camino corto al núcleo con ámbito mínimo

**Estado:** APROBADA (2026-11-26, elegida por el propietario del proyecto)

## Contexto
El ROADMAP ordena Fase 00 → 01 → 02 → 03 → 04. El núcleo de inventario (Fase 04: BP-011/012) depende de identidad, ámbitos, permisos y auditoría (Fase 03: BP-008/009/010). El propietario pidió empezar por el núcleo.

## Decisión
1. Ratificar primero las ADR que gobiernan el núcleo: 005, 006, 014, 016 y 040 (hecho el 2026-11-26).
2. Fundación mínima **solo backend** (Go + PostgreSQL + CI) y los spikes BP-005 (atomicidad/idempotencia) y BP-006 (decimal exacto, lado Go/PostgreSQL) **integrados** en el núcleo como pruebas de aceptación.
3. Implementar BP-011/BP-012 con un **puerto de ámbito mínimo** `application.Scope{CompanyID}`: toda operación exige empresa y el almacenamiento filtra por ella; las claves foráneas compuestas `(company_id, id)` impiden mezclar empresas en la base de datos.
4. Identidad, sesiones, roles, permisos de servidor (ADR-024, pendiente), auditoría y dispositivos siguen siendo Fase 03. Mientras no existan, **no se expone API HTTP de inventario** ni se usa con datos reales.

## Consecuencias
- El núcleo se valida temprano con PostgreSQL real y concurrencia.
- Cuando llegue BP-008/009, `Scope` se construirá desde la sesión autenticada y se añadirá la verificación de permisos antes de cada caso de uso; el núcleo no debe cambiar sus reglas.
- Valoración/costos quedan fuera hasta ratificar ADR-044.
- Lotes, seriales, combos (BP-013), ubicaciones, conteos y bloqueos de calidad quedan pendientes.
