# ADR-171 — Catálogo inicial de unidades base por dimensión

**Estado:** PROPUESTA / RATIFICACIÓN PENDIENTE (implementada en el PR #1 para cumplir ADR-060/061; la lista concreta requiere ratificación)

## Contexto
La revisión correctiva del PR #1 detectó que la unidad base de un SKU era texto libre: se aceptaban "weight" con "und" o "volume" con "kg". Eso contradice ADR-060/061 (unidad base por SKU, conversiones exactas, no convertir kg a litros sin una equivalencia válida).

## Propuesta implementada
- Cada dimensión acepta solo estas unidades base (`domain.baseUnits`, más el `CHECK` de la migración 00003):
  - `unit`: `und`
  - `weight`: `kg`, `g`
  - `length`: `m`, `cm`
  - `volume`: `l`, `ml`
- Las unidades se normalizan a minúsculas.
- Empaques como "caja", "paquete" o "docena" **no son unidades base**: son presentaciones con factor exacto (ADR-060).
- No hay conversión entre unidades base, ni dentro de una misma dimensión (g↔kg) ni entre dimensiones. Todo el stock se lleva en la unidad base del SKU.

## Por ratificar
- La lista concreta, por ejemplo si hacen falta `lb`, `oz`, `gal`, `pulg` o `pie` para ferreterías y para la futura expansión internacional (ADR-042).
- Si un SKU de tipo `unit` debe tener precisión 0 obligatoria. Hoy se permite fraccionar, por la "fracción" de INV-03.
- Ampliar el catálogo exige una migración nueva que reemplace el `CHECK`, junto con el cambio en `baseUnits`.
