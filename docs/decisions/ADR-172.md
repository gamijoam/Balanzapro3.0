# ADR-172 — Desviaciones y añadidos de dependencias no aprobados explícitamente

**Estado:** PROPUESTA / RATIFICACIÓN PENDIENTE

## Contexto
La revisión correctiva del PR #1 comprobó que la ADR-170 se había marcado como APROBADA con decisiones que el propietario no eligió. Se separan aquí para que se ratifiquen o se reviertan.

## Propuestas en uso dentro del PR #1
| # | Propuesta | Motivo | Alternativa si no se ratifica |
|---|---|---|---|
| 1 | **google/uuid v1.6.0** (BSD-3, 2024-01-23) para identificadores | UUID es el identificador del contrato (overview.md); está en TECH_STACK como "Candidato" | `pgtype.UUID`/`[16]byte` propios; cambio mecánico |
| 2 | **Diferir sqlc** | Pocas consultas, casi todas condicionales y con casts NUMERIC→text; se escriben a mano con pgx y se prueban contra PostgreSQL real | Generar las consultas con sqlc (ADR-009 sigue pendiente) |
| 3 | **Diferir testcontainers-go** | El entorno de desarrollo no tiene daemon Docker. Se usa un PostgreSQL desechable vía `BP_TEST_DATABASE_URL` con guardas (pgtest) y un servicio PostgreSQL en CI | Usar testcontainers cuando haya Docker disponible |
| 4 | **make** en lugar de Task | Evita una dependencia nueva | Task (TECH_STACK: candidato) |

## Consecuencias
Mientras no se ratifique, el código usa estas opciones, pero no se consideran decisiones del proyecto. Ninguna afecta a datos ni a contratos públicos: no hay API.
